# Security Policy

## Supported Versions

BetterTot is currently a development preview. Security fixes are applied to
the latest code on `main` and included in the next available build. Older
commits, locally modified builds, and superseded development artifacts are not
supported.

## Reporting a Vulnerability

Do not open a public issue or discussion for a suspected vulnerability. Report
it privately through
[GitHub Security Advisories](https://github.com/saaivignesh20/BetterTot/security/advisories/new).

Include, when possible:

- A description of the issue and its potential impact
- The affected commit, version, and macOS version
- Reproduction steps or a minimal proof of concept
- Any conditions or permissions required for exploitation
- Suggested mitigations, if known

Do not include real note contents, credentials, signing identities, or other
private user data. Use synthetic test data in reports and demonstrations.

## Response Process

Maintainers will aim to acknowledge a report within seven days. After
validation, the report will be prioritized according to impact and
exploitability. Reporters will receive updates when the assessment changes or
a fix is ready.

Please allow maintainers a reasonable opportunity to investigate and release a
fix before public disclosure. Coordinated disclosure timing will be discussed
with the reporter when a vulnerability is confirmed.

## Research Guidelines

Good-faith research should:

- Avoid accessing, modifying, or deleting another person's data
- Avoid privacy violations, service disruption, and social engineering
- Use only accounts, devices, and data you own or are authorized to test
- Stop testing and report the issue if sensitive data is encountered

Reports about vulnerabilities in macOS, GitHub, or other third-party services
should be submitted to the relevant vendor unless BetterTot's own behavior is
the source of the issue.
